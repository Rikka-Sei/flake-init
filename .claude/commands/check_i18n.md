# 国际化命名空间检查命令

## 描述
检查指定文件中使用的翻译键是否符合新的模块化 i18n 架构规范。

## 新的 i18n 架构
- **核心 i18n.sh**: 只包含基础框架，不包含具体翻译
- **模块 i18n**: 每个文件在自己的 `_<namespace>_init_i18n()` 函数中定义翻译
- **命名空间**: 翻译键使用 `<namespace>_<key>` 格式（如 `main_welcome`, `ui_ok`）

## 用法
```bash
/check_i18n <file> <namespace>
```

## 参数
- `file`: 要检查的文件路径
- `namespace`: 要求的命名空间前缀

## 功能
1. **扫描翻译键**: 查找所有 `_t "key"` 调用
2. **检查命名规范**: 验证翻译键是否使用正确的命名空间前缀
3. **检查初始化函数**: 确认是否存在 `_<namespace>_init_i18n()` 函数
4. **验证函数调用**: 确保初始化函数在适当位置被调用
5. **检查翻译完整性**: 确保所有使用的翻译键都在初始化函数中定义

## 示例
```bash
# 检查 flake-init.sh，要求使用 main 命名空间
/check_i18n src/flake-init.sh main

# 检查 ui.sh，要求使用 ui 命名空间
/check_i18n src/lib/ui.sh ui
```

## 检查项目
1. **翻译键命名**: 所有 `_t "key"` 中的 key 必须以 `<namespace>_` 开头
2. **初始化函数存在**: 文件中必须定义 `_<namespace>_init_i18n()` 函数
3. **初始化函数调用**: 函数必须在适当位置被调用（通常在模块加载时）
4. **翻译定义完整**: 初始化函数中必须定义所有使用的翻译键

## 重构建议
如果检查失败，提供以下重构建议：
- 创建缺失的 `_<namespace>_init_i18n()` 函数
- 重命名翻译键添加命名空间前缀
- 将翻译定义从 i18n.sh 移动到模块初始化函数
- 添加初始化函数调用

## 架构优势
- **模块化**: 翻译与业务逻辑分离
- **命名空间隔离**: 避免不同模块间的翻译键冲突
- **按需初始化**: 只有使用的模块才会加载翻译
- **易于维护**: 每个模块管理自己的翻译内容
